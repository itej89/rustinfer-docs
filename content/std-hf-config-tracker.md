# Transformers config v5.23.0 tracker

Gaps found by the [audit](std-hf-config-audit.html) of 2026-11-13, re-audited
against `origin/main` `8c7d47e` on 2026-11-14 after PRs #55, #53 and #49 merged.

| id | gap | required by | status | notes |
|---|---|---|---|---|
| HFC-1 | `rope_parameters` (the v5 layout) was not read; a v5 config lowered with theta 10000 and no scaling, with no error | `modeling_rope_utils.py:679-760`; RI-FE-001 | Fixed 2026-11-13 b99720a | PR #52 (issue #51). `parse_rope` reads `rope_parameters` first, else the v4 `rope_theta`/`rope_scaling` (`crates/rustinfer-frontend/src/arch/llama/config.rs:440-455`); theta from `rope_parameters.rope_theta`, else the top-level key, and a per-layer-type nested object refused naming it (`parse_rope_parameters`, `:461-477`); a config whose two forms disagree is refused naming both fields (`check_forms_agree`, `:480-502`). Tests: `crates/rustinfer-frontend/tests/rope_parameters.rs:66` (theta and scaling from v5), `:84` (v5 defaults), `:99` (v4 still read), `:110`, `:123`, `:142` (agreeing and disagreeing forms), `:157` (R2 kinds still refused), `:186` (refusals name the field, nested form refused), all `Verifies RI-FE-001`. `partial_rotary_factor` was fixed separately (HFC-5, `6a18042`). |
| HFC-2 | Defaults for absent keys follow Llama for every family: `num_key_value_heads` (Mistral 8, Qwen 32), Qwen3 `head_dim` 128, Mistral `sliding_window` 4096, `max_position_embeddings` | `configuration_mistral.py:68-80`; `configuration_qwen2.py:66-75`; `configuration_qwen3.py:67-78` | **Open** | Real exports write these keys, so the risk is hand-made or trimmed configs.
