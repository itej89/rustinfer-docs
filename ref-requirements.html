How the state is derived. By the tag rule of the rustinfer repository's docs/testing.md (set in #27), a test cites a requirement in its doc comment with exactly one of three tags: Verifies RI-X-NNN: <part> only when the clause is fully implemented in the code, Groundwork for RI-X-NNN: <part> while it is not, and Reserved RI-X-NNN (R<n>) for a test asserting a later-release refusal. A requirement is implemented when it has at least one Verifies tag and no Groundwork for tag; partial when it has any Groundwork for tag; reserved only when it has only Reserved tags; and planned otherwise, with its release. The tags are read from the comments of the integration tests under crates/*/tests and the #[cfg(test)] modules under crates/*/src; an id mentioned without a tag word (prose, a //! module header) never counts. The tags column gives the counts as Verifies / Groundwork for / Reserved and the evidence column the files, with the count per file where it is more than one.
