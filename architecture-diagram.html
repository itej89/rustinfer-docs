Architecture diagram

Three rules decide the shape.

A checkpoint is compiled once, ahead of time. Nothing that runs a model reads a Model IR document or plans a kernel. The build writes one artifact for one target and one checkpoint; every load after that verifies it and streams the weights.

Every kernel is generated. Kernel IR, built by Rust generators, lowers in process through the pinned LLVM 23. No vendor kernel library is linked, and no kernel exists as text.

A backend is a crate and one registry line. The graph compiler, the planner and the runtime see only the Target traits; adding hardware changes nothing above them (RI-TGT-004).

The diagrams follow Simon Brown's C4 model: the system in its context, its containers, their components, and their code, each level a zoom into the one before. Beside them are the supplementary views C4 allows: the layers in the Matins form, read from the bottom; the mandatory standards on the element each applies to; the build-then-run sequence; and the one-node deployment of Release 1. A tab switches the level, and each has its own link. Show standards puts each element's standards on the first three levels.

The boxes, their relations and the issues behind them are data, in data/c4/*.json; the dependency bands and the public items are read from the tree's Cargo.toml files and lib.rs; the standards come from data/standards/ through data/standards-placement.json. No chip is typed: each is derived from the issue tracker's last fetch. The shape is the design; the chips are the truth as of 2026-11-14.

      Supplementary The layers, read from the bottom

      The same system as a stack, in the form the Matins site uses.

      The layers of rustinfer

      Read it from the bottom: each band is a layer, the strip between two bands the contract that enforces the boundary, and a layer's name opens its components. The chips are the truth as of 2026-11-14.

      5Interfacespartly built

      One binary, one library, later one server, over the same engine. The CLI is the only crate that names every backend; the library API is enqueue and await (RI-RT-003); the HTTP server is Release 3.

      • CLI: build, inspect, run, tune
      • library API: enqueue, await
      • HTTP server

      4Runtimepartly built

      Loads an artifact and streams the checkpoint's used byte ranges straight to device memory with Sluice, then runs the Plan: static batches first, a KV block pool, the sampler. The planner places the Model IR on the devices it discovered.

      • Sluice weight streamer
      • executor
      • scheduler
      • KV cache
      • sampler
      • planner

      the artifact, hashed and bound to the checkpoint identity; the reader refuses any failed check (RI-ART-003, RI-ART-012)
      3Compilerpartly built

      The frontend reads config.json and the shard headers, picks the family through the Architecture seam and emits Model IR, the weight manifest and the checkpoint identity. The graph compiler turns Model IR into a Plan under a profile; the result is written once as a .rie artifact into the cache.

      • frontend (Architecture seam)
      • Model IR
      • graph compiler
      • Plan
      • .rie artifact cache

      2Kernelspartly built

      Every kernel is generated, none is linked from a vendor library: Rust generators build Kernel IR, a dialect of MLIR, which lowers in process through the pinned LLVM 23 to ROCDL and AMDGPU code objects. The catalog records what each target offers; the autotuner measures the choices.

      • Kernel IR dialect
      • generators
      • MLIR/LLVM 23 lowering → ROCDL, AMDGPU code objects
      • catalog
      • autotuner

      1Targetspartly built

      Target, Device, Catalog and Launcher are the whole contract a backend implements. The CPU reference runs every R1 operator in f32 and is the oracle for the rest. ROCm/HIP is registered for gfx942 and gfx950 with an empty catalog until HIP is bound; riscv-vector, riscv-mesh and spirv-vulkan are registered stubs.

      Supplementary Dynamic diagram for rustinfer: build, then the first run

      What happens between `rustinfer build` and the first token, numbered in order across containers and components. Each step's chip is its component's state; the steps whose code is not written yet are the Release 1 issues still open.

      Build: rustinfer build

      From the checkpoint to a verified artifact in the cache; nothing here needs a GPU.

      1. 1
        Builder → rustinfer CLInot startedrustinfer build <checkpoint> --target gfx950[shell]
      2. 2
        rustinfer-frontend → Checkpoint directorybuiltreads config.json, every shard header and the weight byte ranges it uses (a checkpoint's KV scales); picks the Architecture; emits Model IR, the weight manifest and the checkpoint identity[safetensors, JSON]
      3. 3
        rustinfer-mir → rustinfer-mirbuiltvalidates the Model IR document: shapes, dtypes, encodings, operator arity[in process]
      4. 4
        rustinfer-compiler → rustinfer-plannernot startedruns the pass pipeline to a Plan under the profile; the planner places it on the discovered devices[in process]
      5. 5
        rustinfer-compiler → rustinfer-kcpartly builtasks for each kernel by KernelQuery; generators build Kernel IR, tuned entries come from the catalog[in process]
      6. 6
        rustinfer-kc → LLVM 23 toolchainin PR #44, awaiting hardware testlowers Kernel IR to ROCDL and links an AMDGPU code object per kernel[MLIR C API, lld]
      7. 7
        rustinfer-artifact → .rie artifactbuiltwrites the Plan, the kernels and the manifest; hashes last; fsync and rename into the cache[.rie, SHA-256]

      First run: rustinfer run

      From the artifact to the first token: verify, stream the weights, launch.

      1. 8
        Operator → rustinfer CLInot startedrustinfer run <dir>[shell]
      2. 9
        rustinfer-artifact → .rie artifactbuiltreads and verifies magic, bounds, hash, target and the checkpoint identity; any failure refuses the load[.rie, SHA-256]
      3. 10
        rustinfer-sluice → GPU device boundarybuiltstreams the used byte ranges of the checkpoint into device memory, transforming the layout on the way[pread, HIP copies]
      4. 11
        rustinfer-runtime → GPU device boundarynot startedloads the code objects, launches the Plan, samples a token[HIP]
      5. 12
        rustinfer CLI → Operatornot startedprints the tokens; a client of the library awaits the same responses[stdout]
