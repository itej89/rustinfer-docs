rustinfer

rustinfer is a compiled inference engine for AMD Instinct GPUs and RISC-V accelerators, written in Rust: the model is compiled once per target into a semi-static artifact that is a cache, never an obligation. Its specification says the mission is to be the engine the industry standardises on for those two families, by owning the whole path from model file to machine code: a model is lowered into a Model IR, compiled for one named target into an engine artifact whose kernels rustinfer generates itself from a Kernel IR, and executed by a runtime that makes no graph, kernel, layout or memory decision at inference time. No kernel library, no vendor BLAS, no Python, no NVIDIA.

This site is a reading of the tree at commit 8c7d47e on main, the merge of GitHub PR #49, first written on 2026-11-10, the day the project was specified and scaffolded, and refreshed on 2026-11-11, 2026-11-12, 2026-11-13 and 2026-11-14. Everything on it was read from the source, the SRS, the ADRs and the planning documents in docs/; nothing was run on a GPU. Where a page describes behaviour that does not exist yet it says so and names the issue that will add it.

The shape it is built into

Three decisions produce everything else; they are set out in full under design.

Three representations and nothing else between a model file and the device. The Model IR is a typed SSA graph with profile-bounded dynamic dimensions that every frontend lowers to and every backend consumes. The Kernel IR is a tile-level MLIR dialect with explicit layouts and no thread identity, emitted by Rust generator functions. Two of the three are in the code: the Model IR as rustinfer-mir since Codeberg PR #19, and the Kernel IR as the kir dialect of rustinfer-kc since GitHub PR #25; the launch form the Plan will be made of, Launch in rustinfer-target, exists since GitHub PR #21, the Plan itself (#10) does not. The Plan is the static schedule the executor runs verbatim. ADR-005 calls this Apple's arrangement applied to data-centre inference.

Every kernel is generated, autotuned and validated. There is no kernel library and no vendor BLAS. Generators emit Kernel IR; the kernel compiler lowers it through MLIR to AMD code objects, through MLIR's spirv dialect for Vulkan-class devices, and through rustinfer's own lowering to RISC-V vector and mesh targets. No kernel enters the catalog without validation against the CPU reference target. In the code since GitHub PR #21: the Target trait family, the registry, the CPU reference with every R1 operator, and the catalog selection that serves only an entry validated on the catalog's architecture; every other target's catalog is empty.

The artifact is a cache, and strict mode makes it a requirement. build writes a .rie file; run and serve build the same file on first load and reuse it; --require-prebuilt refuses to build at start. ADR-006 records why the mandatory build step of the TensorRT engine model was dropped and its properties kept.
