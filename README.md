# rustinfer, read from the tree

Documentation for rustinfer, the compiled inference engine for AMD
Instinct GPUs and RISC-V accelerators written in Rust. The pages were written
by reading the repository at one commit (the SRS, the ADRs, the planning
documents, the UML diagrams and the crates) and are meant to be the map of
it: what the three representations are, how a model file becomes an
artifact and an artifact becomes tokens, what exists today, and what each
release adds.

## Building the site

Markdown in, one stylesheet, and a navigation built from the files
themselves. The only dependencies are `markdown` and `pygments`; diagrams
are drawn in the browser by mermaid.js from a CDN.

    python3 -m venv .venv
    .venv/bin/pip install markdown pygments
    .venv/bin/python build.py --serve

Then open <http://localhost:8080>. `./serve.sh` does the last step.

## Publishing

The site is served by GitHub Pages at
<https://itej89.github.io/rustinfer-docs/> from the `pages` branch of
this repository (`github.com/itej89/rustinfer-docs`, root path, with a
`.nojekyll` file so underscore-prefixed files are served). `./publish.sh`
rebuilds `out/`, checks the links, writes the result as a single commit on an
orphan `pages` branch and force-pushes it to `origin`; `main` keeps the
sources only. Run it after every content change you want visible. The site
moved from Codeberg Pages on 2026-11-12 together with the project
(ADR-008); the `codeberg` remote is kept for history and is not pushed to.

## Where the content comes from

`content/*.md` are the pages, each with a small header naming its title,
section, group and order. The sections are Overview, Design, Compiler,
Runtime, Hardware, Development, Trackers, Reference and Standards. The
Standards section holds a hand-written overview (`standards.md`) and the
generated tracker.

Seven pages are generated by `scripts/reference/*.py` from the rustinfer
checkout named by `RUSTINFER_SRC` (default `../rustinfer`) and must be
regenerated, not edited; each carries a comment saying so:

| page | script | reads |
|---|---|---|
| `ref-requirements.md` | `gen_srs.py` | `docs/SRS-RI-v0.1.md`; the requirement tags (`Verifies`, `Groundwork for`, `Reserved`, the rule of the rustinfer repository's `docs/testing.md`) in the comments of `crates/*/tests/**/*.rs` and the `#[cfg(test)]` modules of `crates/*/src/**/*.rs`, from which each requirement's state (implemented, partial, reserved only, planned) is derived in `common.py`; the tracker state (live or `data/progress-snapshot.json`) for the Epic #1 checklist, shown beside it as information; the SRS's own status field |
| `ref-constants.md` | `gen_constants.py` | `crates/rustinfer-core/src/config/constants.rs` |
| `ref-error-codes.md` | `gen_errors.py` | every crate's `src/error.rs` |
| `ref-crates.md` | `gen_crates.py` | `Cargo.toml` and each crate's manifest |
| `design-diagrams.md` | `gen_diagrams.py` | `docs/uml/*.md` |
| `ref-standards.md` | `gen_standards.py` | `docs/SRS-RI-v0.1.md` §1.4 (references), §3.1.3 (external interfaces) and the requirement texts, with the requirement states of `common.py`; `data/standards-candidates.json`, the hand-curated standards the tree depends on that §1.4 does not reference yet (its evidence lines are checked against the checkout) |
| `issues.md` | `gen_progress.py` | GitHub's issues, pull requests, milestones, branches and Actions runs for `itej89/rustinfer`, read live through `gh api` when `gh` is authenticated, else `data/progress-snapshot.json`; the tree for tests and lines |

    for s in scripts/reference/gen_*.py; do .venv/bin/python "$s"; done
    .venv/bin/python build.py
    .venv/bin/python scripts/check_links.py

`check_links.py` fails if any internal link or fragment in `out/` does not
resolve.

The Progress page is not a file: `progress.py`, ported from Matins, is
imported by `build.py` and scans every page for tracker tables (a first
column of ids such as `R1-3`, `OI-009`, `RI-KC-002`, `ADR-005` and a Status
column), classifies each row from the start of its status cell, and draws
the pies. A page whose header says `cards: headings` gets one card per
`##` heading (the requirements page, one per SRS component). The footer names the commit the site was built against, read from
the checkout at build time.

## When the tree moves

Regenerate the generated pages, rebuild, run the link check, and re-read the
dated claims on the index, the trackers and the retracted-conclusions table.
Everything published here was read from the source at the commit named in
the footer. Nothing was run on a GPU; the one command that was executed is
the session on the getting-started page, on the development host.
