Supported models

Read from SRS §3.2.2 (RI-FE), §2.4, the feature inventory and the use cases at commit 082df51.

No model runs today. Since GitHub PR #24 (2026-11-12) the frontend lowers four families into Model IR, a weight manifest and a checkpoint identity, but there is no graph compiler, build, ROCm target or executor to take the result to a token. The table below is the plan the SRS commits to (v0.3, at commit 04a2a26), with the release each row names and its status today.

Input format

The only input is a Hugging Face model directory: config.json, *.safetensors with an optional index, generation_config.json and the tokenizer files (SRS §3.1.3). There is no intermediate checkpoint format, by decision: the feature inventory marks TensorRT-LLM's convert_checkpoint step as adopted without the intermediate. From R2 a model may also be given as a Model IR JSON document (RI-FE-008). Safetensors headers are parsed in Rust, in-tree, by one reader in rustinfer-artifact that the frontend and Sluice share since PR #30 (OI-004).

What a model needs from the rest of the engine

A family is supported when every operator its lowering emits has a catalog kernel on the target. The R1 operator set (RI-MIR-004) is the LLaMA subset: embedding, matmul, rmsnorm, rope, attention prefill, paged attention decode, KV cache write, silu_and_mul, residual add, quantize, logits head and sample. collective arrives in R2 and moe_route, moe_experts and lora_apply in R3, which is why the MoE and LoRA rows above cannot come earlier.

Refusals are typed and happen before any device work (goal 6 of the SRS): an unsupported model_type is rejected naming it and the supported list (RI-FE-003); a checkpoint with a missing or unexpected parameter fails naming the first one (RI-FE-002), because the SRS's rationale is that a silent weight mismatch is wrong output, not an error.

Precision per release

The formats follow the AMD matrix cores (RI-MIR-003, RI-GC-004): bf16, fp16, fp32, fp8 (OCP e4m3 on gfx950, FNUZ e4m3 on gfx942), MXFP4 (fp4x2 with ue8m0 scales, SRS v0.4) and the fp8, MXFP4 and bf16 KV cache in R1, plus OCP E5M2 (fp8_e5m2, SRS v0.4.6, PR #55), which only quantize and dequantize take; int8 in R2; int4 weight-only in R3.
