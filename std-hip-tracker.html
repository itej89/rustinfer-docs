HIP runtime API ROCm 7.2 tracker

Gaps found by the audit of 2026-11-13, re-audited on 2026-11-14 against main 81fbcba after PR #58 (issue #12, merge 53dac5b) bound the HIP runtime and PR #44 (merge 38f2f60) moved its GPU tests onto that binding. The binding's hardware test #59 passed on an MI350X (gfx950) under ROCm 10.1 (10.1.0-3), HIP runtime major 7, at bb0ce2f, the head PR #58 merged: 11 passed, results in #54. gfx942 is not yet run; that is #61, recorded as HIP-13. Paths are under crates/rustinfer-target-rocm/ unless named otherwise.

id gap required by status notes
HIP-1 No device enumeration, selection or properties; the architecture is not read from gcnArchName Device management: hipGetDeviceCount, hipSetDevice, hipGetDeviceProperties Fixed 2026-11-14 53dac5b #12, PR #58. open_devices and open_device (src/lib.rs:140-186) call hipRuntimeGetVersion, hipGetDeviceCount (hipErrorNoDevice is an empty host, :143-149), hipGetDeviceProperties (bound as hipGetDevicePropertiesR0600, src/ffi/symbols.rs:71) and hipSetDevice; the processor and the sramecc/xnack settings come from gcnArchName (TargetId::parse, src/arch.rs:32), and another architecture is refused naming both (src/lib.rs:94-110). Tests (all Verifies RI-ROC-003): test_gcn_arch_name_suffixes_are_stripped_and_read (tests/architecture.rs:24), test_device_architecture_comes_from_gcn_arch_name (:57), test_gfx942_target_is_refused_on_a_gfx950_device_naming_both (:77), test_malformed_gcn_arch_name_is_refused (:184); test_no_device_status_means_an_empty_host (tests/errors.rs:253, Verifies RI-ROC-002). gfx950: verified by #59 (gpu_device_reports_its_architecture, architecture=gfx950, lds_bytes=163840; both refusals name gfx942 and gfx950). The bare-name dlopen noted here before is gone: see the audit's RI-SEC-001 note
HIP-2 No device memory in the target Memory management: hipMalloc, hipFree, hipMemcpyAsync Fixed 2026-11-14 53dac5b #12, PR #58. hipMalloc, hipFree, hipMemcpyWithStream (host to device and back) and hipMemcpyAsync (device to device) are bound (src/ffi/symbols.rs:72-75); a zero-byte allocation is refused before hipMalloc, which would return a null pointer with success (src/device/mod.rs:243-253); free waits on the buffer's last-use events before hipFree (src/device/lifetime.rs). Tests (Verifies RI-ROC-001): test_memory_round_trip (tests/device.rs:37), test_zero_byte_allocation_is_refused_without_calling_hip (:75), test_unknown_handles_and_bad_ranges_are_refused (:88), test_free_waits_for_a_device_copy (tests/lifetime.rs:73). gfx950: verified by #59 (memory_round_trip bytes=1048576 mismatches=0 offset_mismatches=0, free_while_in_use mismatches=0)
HIP-3 No streams Stream management Fixed 2026-11-14 53dac5b #12, PR #58. hipStreamCreateWithFlags, hipStreamSynchronize, hipStreamDestroy (src/ffi/symbols.rs:76-78); create_stream and synchronize (src/device/mod.rs:284-289, :359-365); Drop synchronises and destroys every stream (:436-456), tested by test_drop_releases_every_hip_resource (tests/device.rs:463, Verifies RI-ROC-001) and test_drop_waits_for_in_flight_work (tests/lifetime.rs:118). One stream per iteration (RI-RT-008) is the runtime's to use; the runtime is not built yet. gfx950: verified by #59 (stream_event_ordering)
HIP-4 No events Event management Fixed 2026-11-14 53dac5b #12, PR #58. hipEventCreateWithFlags, hipEventDestroy, hipEventRecord, hipEventSynchronize, hipEventElapsedTime and hipStreamWaitEvent (src/ffi/symbols.rs:79-84); record and wait (src/device/mod.rs:300-318). Tests: test_event_timing_maps_hip_failures (tests/errors.rs:136, Verifies RI-ROC-002), test_failed_last_use_record_synchronises_the_stream (tests/lifetime.rs:197, Verifies RI-ROC-001). gfx950: verified by #59: a consumer waiting on the producer's event always saw its result (ordered_mismatches=0) and a control run without the wait did not (unordered_wrong=327680), with a 30.4 ms producer
HIP-5 No module loading in the target Module management: hipModuleLoadData, hipModuleGetFunction, hipModuleUnload Fixed 2026-11-14 53dac5b #12, PR #58. load_module (src/device/kernels.rs:150-170) runs only after check_code_object (:102-120) has parsed the code object, matched its processor and features to the device and passed the RI-ROC-004 resource check; modules are unloaded on drop. Tests (Verifies RI-ROC-001): test_load_refuses_other_formats_and_missing_kernel_ir (tests/device.rs:404), test_load_refuses_unbound_arguments_and_several_kernels (:433); test_binary_for_another_architecture_is_refused_before_loading (tests/architecture.rs:98, Verifies RI-ROC-003). RI-ROC-004's "only after the artifact check" (RI-ART-003) needs the runtime that calls load, not built yet. gfx950: verified by #59 (module_load_and_launch kernel=fill items=65536 mismatches=0)
HIP-6 No kernel launch in the target Execution control: hipModuleLaunchKernel Fixed 2026-11-14 53dac5b #12, PR #58. Three-dimensional grid and block on any stream (launch_with, src/device/mod.rs:150-158); every dimension must be at least 1 and grid times block below 2^32 (check_dims, src/device/kernels.rs:316-331; ROCM_MAX_WORK_ITEMS_PER_DIMENSION, crates/rustinfer-core/src/config/constants.rs:423), so the limit noted before is now checked. Tests (Verifies RI-ROC-001): test_launch_runs_the_kernel_on_its_operands (tests/device.rs:289), test_explicit_dimensions_and_the_work_item_limit (:326), test_unknown_kernel_and_operand_count_are_refused (:368). gfx950: verified by #59
HIP-7 HIP errors not mapped to a typed error in the target Error handling: hipError_t, hipGetErrorString Fixed 2026-11-14 53dac5b #12, PR #58. Every call goes through Hip::call (src/runtime.rs:23-29), which makes Error::Hip { operation, code, message } with hipGetErrorString's text (src/runtime.rs:44-52, src/error.rs:31-40), the fields #12 asked for; release paths log instead (src/runtime.rs:33-42). Tests (Verifies RI-ROC-002): test_device_calls_map_hip_failures_to_typed_errors (tests/errors.rs:72), test_module_and_launch_calls_map_hip_failures (:158), test_graph_calls_map_hip_failures (:180), test_device_discovery_maps_hip_failures (:211), test_hip_error_structured_line (:230); test_hip_error_names_the_call_with_code_device (tests/error_contract.rs:24, Verifies RI-CLI-001). hipGetErrorName is not bound; nothing requires it. No HIP failure occurred in #59 to show a real string
HIP-8 No check of a kernel's LDS and register needs before its first launch Execution control: hipFuncGetAttribute; hipDeviceProp_t Fixed 2026-11-14 53dac5b #12, PR #58. hipFuncGetAttribute is not bound: the needs are read from the code object's NT_AMDGPU_METADATA note before hipModuleLoadData (src/code_object/), which is what the check "before the first launch" needs. LDS, work-group and wavefront limits come from sharedMemPerBlock, maxThreadsPerBlock and warpSize; the register limits from AMDGPUUsage, since regsPerBlock is always 0 (DeviceLimits::check, src/resources.rs:63-81; constants crates/rustinfer-core/src/config/constants.rs:400-418). Tests (Verifies RI-ROC-004): test_kernel_over_the_lds_limit_is_refused_before_loading (tests/resources.rs:56), test_lds_limit_is_the_devices_sharedmemperblock (:76), test_registers_past_the_architecture_limits_are_refused (:104), test_work_group_and_wavefront_size_are_checked (:125), test_work_group_registers_must_fit_the_compute_unit (:148), test_required_work_group_size_bounds_the_waves (:165). gfx950: verified by #59 for LDS (163840 bytes launches, 163844 refused naming the kernel); the register limits are not exercised on hardware
HIP-9 HIP runtime version not recorded or compared Initialization and version: hipRuntimeGetVersion, hipDriverGetVersion Fixed 2026-11-14 53dac5b #12, PR #58; rule restated by SRS v0.4.10 (PR #62, merge 81fbcba). hipRuntimeGetVersion is read when the devices open; a major version (version / 10000000) other than 7 is refused naming the found, its major and the required version (check_version, src/lib.rs:157-169; ROCM_HIP_RUNTIME_MAJOR, crates/rustinfer-core/src/config/constants.rs:391), and the version is a manifest line (src/lib.rs:150, log_manifest_runtime, crates/rustinfer-core/src/manifest.rs:103-105). Tests: test_runtime_of_another_major_version_is_refused (tests/errors.rs:278, Groundwork for RI-NFR-017), test_hip_library_and_runtime_are_manifest_lines (crates/rustinfer-core/tests/manifest_log.rs:39, Verifies RI-SEC-001). Not done: hipDriverGetVersion is not bound (no requirement needs it), and the artifact header records no HIP major version; with only major 7 accepted that is not yet needed for RI-NFR-017, but supporting a second major would need it. #59 passed the check, so ROCm 10.1 (10.1.0-3) ships a HIP 7.x runtime
HIP-10 No graph capture binding Graph management: hipStreamBeginCapture, hipStreamEndCapture, hipGraphInstantiate, hipGraphLaunch Fixed 2026-11-14 53dac5b #12, PR #58. All four, with hipGraphDestroy and hipGraphExecDestroy, are bound (src/ffi/symbols.rs:91-96); capture in thread-local mode, one graph per segment, failed captures ended (src/device/graph.rs:27-128); replay and the eager fallback (:171-224); an exec is destroyed only after its last use (:130-148). Tests: test_capture_makes_one_hip_graph_per_segment (tests/graph.rs:69), test_failed_capture_ends_the_capture (:160), test_hip_failure_while_capturing_ends_the_capture (:188) (Groundwork for RI-TGT-005); test_recapture_waits_for_the_replaced_graph (tests/lifetime.rs:104, Verifies RI-ROC-001). gfx950: verified by #59 (graph_capture_replay graph_launches=5 host_syncs=0; graph_destroy_while_in_use destroyed 0.017 ms after the 30.4 ms replay finished)
HIP-11 No graph replay per bucket Graph management Later release R2 RI-ROC-007. The device contract already captures per bucket (Device::capture(stream, bucket, launches), crates/rustinfer-target/src/target.rs:128); the per-bucket plan is R2
HIP-12 No peer access discovery Peer to peer: hipDeviceCanAccessPeer Later release R2 RI-PLN-002. Not bound on 81fbcba
HIP-13 The HIP binding has not run on gfx942 hardware H1 to H10 on an MI300X (gfx942): 64 KiB of LDS, its own gcnArchName Open GPU test #61, not yet run: the steps of #59 on an MI300X, expecting 11 passed; 0 failed, lds_bytes=65536 and the over-limit kernel refused at 65540. The owner merged PR #58 on the gfx950 result alone (#54)
