Roadmap

The sequence, decided 2026-11-10 in the Epic (#1). Its logic is that the first step fixes the rules and the dependency graph so every later step is one crate's worth of work behind a gate, and that the two compiler chains (the Model IR chain and the Kernel IR chain) can proceed side by side until the graph compiler joins them.

Today a change means an issue, a branch named after it, tests that cite requirement ids, the post-coding gate, and a pull request whose template is the standard's 15-step checklist. Nothing runs a model; every subcommand of the one binary validates its arguments, build and tune resolve their --target through the registry, and each answers not_implemented. Eight components have behaviour, all merged by 2026-11-12: the core, the Model IR, the artifact, the planner interfaces, the target abstraction with the CPU reference, Sluice, the LLaMA-family frontend and the Kernel IR with its MLIR link. The tech-debt work of #27 merged on 2026-11-13 and closed it. On the same day MXFP4 moved into Release 1 (SRS v0.4, ADR-010), and its first three pieces merged: the dtypes and the conversion oracle (#34), the manifest and Sluice (#39), the KV dtypes on the CPU reference (part of #37); the 25 mandatory standards were audited and the defects found on main fixed (#51, PR #52). Late on 2026-11-13 (US Central; 2026-11-14 UTC) three more merged: OCP E5M2 and the partial_rotary_factor refusal (PR #55, SRS v0.4.6), the build allowed to read weights with the artifact bound to the ranges it used (PR #53, SRS v0.4.7), and the Quark and compressed-tensors MXFP4 checkpoint import with checkpoint KV scales (PR #49, #35 closed, SRS v0.4.8). The AMD lowering (#8) is PR #44, waiting on GPU test #45; the graph compiler (#10) waits on #9, which waits on #8.

The progress page is this roadmap's measure: every tracker on this site counted by state, the issues first, then the requirements by component, then the rest.

0. Specify — done, 2026-11-10

The TensorRT-LLM feature inventory, 24 use cases and the AMD and RISC-V device inventory, then SRS-RI-v0.1 with 171 requirements in 27 groups, every one tagged R1 to R4, and ADR-001 to ADR-006. The owner approved it on 2026-11-11 and PR #16 merged into main as 1c7a008 on 2026-11-12, carrying v0.2 with 186 requirements in 28 groups. The Epic and the fourteen issue bodies were drafted in the tree before the tracker existed so the numbers would match the branch names.

One defect stood between here and there: ADR-002, written before the SRS was rewritten, still listed six artifact sections under retired RI-ENG and RI-CMP ids while RI-ART-002 lists nine plus lora_slots. Found by the first reading for this site on 2026-11-10; corrected on the docs branch on 2026-11-11.

1. Scaffold (#2) — done, 2026-11-11

Fourteen crates, one per box of the component diagram, dependencies downward only and enforced by Cargo; rustinfer-core with constants defined once, typed settings read once, the StructuredError contract and ten error codes, key=value logging with ISO-8601 timestamps, and a version manifest whose dependency versions come from Cargo.lock at build time; the rustinfer command with its six subcommands parsed, paths canonicalised at the boundary, --require-prebuilt refusing a directory, one error line on stderr and exit codes 1 and 2; CI as lint → security → test → build; every mandatory file (design, build steps). 40 tests, 89.15 percent line coverage, clippy pedantic and rustdoc clean, zero unsafe.

Three defects stood between the green build and the gate, found by the post-coding audit of 2026-11-11 and fixed in e91e002:

  • Two functions were over the standard's 20-line rule: the command dispatcher at 54 body lines and the manifest builder at 27. Both were split, one function per subcommand.
  • The calendar arithmetic that produces timestamps carried its day-count constants as bare literals; they are now named.
  • run and serve duplicated the artifact-source check; it is one shared function.

A fourth was in the pipeline, not the code. The workflow asked for ubuntu-latest, a label Codeberg's hosted runners never answer, so the first two CI runs of 2026-11-11 sat unclaimed and were cancelled. Every job now runs on codeberg-medium within its ten-minute limit, with the actions pinned to full commit SHAs, permissions: contents: read and timeout-minutes: 10, and the two tools the jobs install are prebuilt binaries so they fit; ADR-004 records the labels and that the LLVM-linking steps will not fit a hosted runner at all. Since the move to GitHub on 2026-11-12 (ADR-008) the jobs run on ubuntu-latest again, the label the workflow first asked for (build steps).

Three more were Codeberg's own rules, and they went with Codeberg. Once the repository was public, the hosted runners answered, and runs 3 to 6 each failed one step further along: short action names resolve against data.forgejo.org, which mirrors only actions/*; cargo-deny reads version-less workspace path dependencies as wildcards; and upload-artifact v4 refuses any host but github.com. Each got a one-line fix and a sentence in ADR-004 (ac68ff1, b252ea6, d380d0a, cc3e293), and run 7 was green across lint, security, test and build.

Where it stands. PR #17 merged into main as 33fadd0 on 2026-11-12 after PR #16, with CI green on run 8 and on run 9 for main; issue #2 is closed. main holds the approved SRS, the six ADRs and the fourteen-crate workspace, and every later branch has its base.

2. Model IR (#3) — done, 2026-11-12

The typed SSA graph every later step consumes, as the crate rustinfer-mir (design): a Document holding one weight set as tensor descriptors (name, dtype, shape, an encoding when quantized, a placement slot) and never a weight byte; the named functions prefill and decode, each a list of nodes in definition-before-use order; KV groups the attention nodes name; the twenty operators of RI-MIR-004 in one static registry of release, arity and dtype rules; a validator that refuses the first fault naming the function, the node and the field; canonical JSON (sorted keys, compact) that round-trips byte for byte, under ir_version 2 since PR #32 (2026-11-13; an all-empty version 1 document still reads); and a bounded three-phase reader. PR #19 merged into main as 2d75c5d on 2026-11-12 with CI green on run 10; 201 workspace tests, 95.50 percent line coverage in the PR's checklist. The schema is docs/api/model-ir.md in the tree and the read path is sequence diagram §4 (design diagrams).

Two readings the PR records rather than decides: the Profile is a type of the crate but not part of the document, because ADR-002 stores it as its own artifact section; and "quantized tensors carry an encoding" is enforced as an encoding present exactly when the dtype is fp8.

3. Artifact (#4), target abstraction and CPU reference (#5), LLaMA frontend (#6) — done, 2026-11-12

The artifact (#4) merged into main as 678b084 on 2026-11-12 (Codeberg PR

21, the last before the move): the crate rustinfer-artifact with the

.rie header, the section table, the content hash, the verifying reader and the atomic writer, and issue #4 is closed. The target abstraction (#5) merged into main as f039b4d the same evening (GitHub PR #21, a different pull request from the Codeberg one of that number): rustinfer-target with the Target, Catalog, Device and Launcher traits, the Registry resolving an architecture string and nothing else, the CPU reference target with every R1 operator as f32 functions, the numeric conversions for bf16, fp16 and fp8, the four backend crates as stubs with an empty catalog and no device, and the command's registry of six strings; 527 workspace tests passed and 96.44 percent line coverage in the PR's final test run; issue #5 is closed (design, hardware).

The LLaMA-family frontend (#6) merged into main as 84449e7 on 2026-11-12 (GitHub PR #24) and issue #6 is closed: rustinfer-frontend lowers llama, mistral, qwen2 and qwen3 from config.json, the optional shard index and the safetensors headers into a validated Model IR document, the weight manifest and the checkpoint identity, reading no weight byte; everything that differs between architectures sits behind the crate-internal Architecture trait and its model_type registry; the safetensors reader is in-tree Rust (OI-004), shared with Sluice in rustinfer-artifact since PR #30. 86 frontend tests, 672 in the workspace in the PR's checklist. What the Model IR cannot yet say is refused by name: Qwen3 QK norm (#26), llama3, yarn and dynamic RoPE scaling (#31, R2), sliding windows; mixed dtypes were lifted by PR #33 on 2026-11-13, with a dtype expectation per tensor (frontend).

4. Kernel IR and the MLIR link (#7), AMD lowering (#8) — #7 done, 2026-11-12; #8 next

The Kernel IR (#7) merged into main as ad51bce on 2026-11-12 (GitHub PR

25) and issue #7 is closed: the kir dialect as a Rust operation table

from which the IRDL MLIR loads is generated, the typed KernelBuilder, and behind the mlir feature KernelContext, which verifies the text, lowers it for the host and translates it to LLVM IR in-process, byte-identical across contexts and threads. ADR-007 resolves OI-009: LLVM 23.1 from apt.llvm.org, melior 0.29.1, a static link, the install script in CI, and an extracted prefix for developers without sudo (kernel compiler). The workspace MSRV became 1.89; 718 workspace tests passed with all features in the PR's final run.

The dependency that was easy to miss, settled. Linking LLVM did not fit Codeberg's ten-minute hosted runner, which is why ADR-004 named a self-hosted runner early. On GitHub's hosted runners the install script and the link stay inside the ten-minute job timeout, so ADR-007 needs no self-hosted runner.

Next: the AMD lowering (#8), unblocked since #7 closed: the gpu → rocdl → AMDGPU lowering with MFMA, LDS and bounds-checked loads for gfx942 and gfx950, complete when the code objects assemble and disassemble as expected on a host without a GPU. The PR #25 review moved one criterion here from #7: a module compiled to a code object in-process through the LLVM C API and lld as a library, byte-identical when built twice, with liblld-23-dev added to the install script.

5. Generators, catalog and autotuner (#9)

The R1 generator set, the catalog with validated-hardware records, and rustinfer tune. Blocked on #5 and #8, and on hardware: the autotuner runs on an MI300X or MI355X, which is not on the bench (OI-008; the recorded resolution is to rent an MI355X node). This is the first step that cannot complete on a laptop.

6. Graph compiler (#10), then build and inspect (#11)

Where the two chains meet: the logged pass pipeline from Model IR to Plan (graph compiler), blocked on #3, #5 and #9; #3 and

5 are closed, so #10 waits on #9 alone, and #9 on #8. The graph compiler

consumes the version 2 placement slot of ADR-009 from its first commit; then build and inspect wired through frontend, compiler, kernel compiler and artifact writer, with the cache-keyed first-load build of ADR-006 (artifact as cache), blocked on #4, #6 and #10.

7. ROCm target (#12), executor (#13), run (#14)

The HIP binding behind one ffi module, raising the unsafe budget from zero by exactly its count, blocked on #5 and on hardware; the static-batch executor with the O(1) KV block pool and the one-launch sampler, blocked on

10 and #12 (runtime); and run end to end, blocked on #11

and #13, which closes the Epic's acceptance criteria: a LLaMA checkpoint built for cpu and gfx950, inspected without a GPU, generating the same tokens on the CPU reference and an MI355X, every generator autotuned and validated, CI green.

8. Planner interfaces (#15) — done, 2026-11-12

The topology model and the single-device placement that fills the Model IR's slots, unblocked since #3 closed and off the critical path. GitHub PR

20 merged into main as d886a3c on 2026-11-12 and issue #15 is closed:

rustinfer-planner with Topology (devices, memory tiers, links, offload engines) in and out of canonical JSON under topology_version 1, Placement (a tier per tensor, a device per node path, the strategy and explained decisions) under placement_version 1 (2 since PR #32, a device, tier and shard per tensor), the Planner trait, SingleDevicePlanner refusing a model whose footprint at the profile's max exceeds the device's local tier, and place, the one call the rest of R1 makes; discovery and the cost-model planner answer not_implemented until Release 2, as the owner decided (planner). The schema is docs/api/topology.md in the tree.

9. Sluice, the weight streamer (#18) — done, 2026-11-12

Blocked by #4 and #5, both closed on 2026-11-12, and blocking the executor (#13). GitHub PR #23 merged into main as add4752 on 2026-11-12: rustinfer-sluice verifies the checkpoint identity and every needed tensor's header before reading a byte, reads exactly the rank's byte ranges through a staging pool bounded by RUSTINFER_STAGING_BYTES, applies the identity, transpose and pad transforms on the device, overlaps reads, copies and transforms on three threads, and digests every needed tensor for --verify-weights (Sluice). 57 crate tests, 587 in the workspace, 96.43 percent line coverage in the PR's run. Issue #18 closed on 2026-11-13.

11. MXFP4 in Release 1 (#34 to #39) — in progress

12. Standards conformance (#51) — fixes merged 2026-11-13

SRS v0.4.2 (PR #46, e7dbdc6) cites the 21 external standards the requirements depend on; v0.4.3 (PR #50, 48c2820) classes each §1.4 reference mandatory R<n> with a scope, process, informative or internal, adds OI-016 (the minimum Vulkan and SPIR-V version, open) and narrows OCP OFP8 to saturating conversion only. The standards were re-audited at 8c7d47e on 2026-11-14.

What comes next

Release 2, production serving: in-flight batching, chunked prefill, the overlap scheduler, prefix reuse on by default, HIP graphs, tensor parallelism on one node, metrics and bench; 41 requirements, no issues yet. Then Release 3, the industry-standard feature set (33 requirements) and Release 4 (4). The release plan has each.
