Features

Read from the SRS by component and from docs/feature-matrix.md at commit 082df51. A status of Supported means tested in the tree; Planned Rn means a requirement and, for R1, an issue exist; Not started is used where the SRS names the release but no issue has been opened yet (every R2 to R4 row). On 2026-11-12 the supported rows are the core, the Model IR, the artifact, the planner interfaces and the targets, all on main.

The feature combination matrix

docs/feature-matrix.md is kept from the first release (RI-NFR-015). Its rule, from the file: a combination not marked S is refused at build or at admission, never attempted (RI-SEC-005, RI-GC-014). U is unsupported by design, T untested, and – not yet implemented in any release. A cell moves from – to S only with a test that exercises the pair.

On 2026-11-10 one cell is S: static batch with itself. Every other pair is –, except the decisions carried from the TensorRT-LLM inventory:

pair marking reason recorded
in-flight batching, chunked prefill × static batch U the policies exclude each other
tree speculation × sliding window U carried from the inventory; also refused with MLA (RI-SPD-004)
beam search × sliding window U carried from the inventory (RI-KVC-009)
speculation × pipeline parallelism U not a column until R4 (RI-SPD-004)
LoRA × TP, LoRA × EP, speculation × LoRA T combinations to be tested, not assumed

The columns are static batch, IFB, chunked prefill, prefix reuse, FP8 KV, sliding window, TP, EP, LoRA, linear speculation, tree speculation, guided decoding, beam search, overlap scheduler and HIP graph. The lower triangle is authoritative; the graph compiler will read the file's state and refuse an unlisted pair naming it (RI-GC-014).
