Read open PR #44 (branch feat/8-amd-lowering, head 10b8b1b): crates/rustinfer-kc/src/mlir/llvm.rs, emit.rs, code_object.rs, lld_shim.cpp, crates/rustinfer-target-rocm/src/ffi/hip.rs and the tests crates/rustinfer-kc/tests/amd_lowering.rs and crates/rustinfer-target-rocm/tests/gpu_code_objects.rs. Result

On main rustinfer produces no code object, so no item conforms. PR #44 configures the back end for exactly the V5 amdhsa form (triple, pinned version, processor, unforced XNACK and SRAMECC, PIC, lld -shared) and its host tests pin the header fields the HIP loader checks first. The parts of the object the loader reads next (the metadata note, the .kd symbols and the kernel descriptor) are produced by LLVM and are not checked by any test; the hardware run of #45 would exercise them by loading and launching each object. Gaps are on the tracker.
