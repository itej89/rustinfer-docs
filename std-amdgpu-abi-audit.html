AMDGPU code object V5 audit

Audit of 2026-11-14, against the requirements; it replaces the audit of 2026-11-13, which read PR #44 before it merged.

Method. Read main at 81fbcba (after the merges of PR #58, 53dac5b, and PR #44, 38f2f60): crates/rustinfer-kc/src/mlir/llvm.rs, emit.rs, code_object.rs, lld_shim.cpp, build.rs, the tests crates/rustinfer-kc/tests/amd_lowering.rs and tests/code_object/mod.rs; the ROCm target's reader crates/rustinfer-target-rocm/src/code_object/, src/device/kernels.rs, src/resources.rs and its tests code_object.rs, code_object_golden.rs, resources.rs, architecture.rs, gpu_code_objects.rs and gpu.rs. Read the hardware results of #45 and #59 in #54: an MI350X (gfx950) under ROCm 10.1 (10.1.0-3), 2026-11-15 (UTC);

45 ran at 821a57e (PR #44 before its rebase onto #58's target), #59 at

bb0ce2f (the head PR #58 merged). Compared each field with the AMDGPUUsage text at llvmorg-23.1.0. Nothing was built or run locally. Test tags follow docs/testing.md. "Hardware" below means gfx950 verified (#45, #59) and gfx942 not yet run (#61).

Cache-policy bits, audit of 2026-11-15

Against AB-R16, added to the scope by SRS v0.4.11 (PR #65), on main b057ef5. Read the Load-Visible and Store-Available tables and the non-atomic code sequences of Memory Model GFX942 and Memory Model GFX125x; read crates/rustinfer-kc/src/capabilities.rs and the ROCDL lowering (crates/rustinfer-kc/src/mlir/rocdl/) and searched every crate for sc0, sc1, nt, nontemporal and cache-policy spellings. No test run.

id result evidence
AB-R16 missing (ABI-5) The capability description has no cache-policy hint (capabilities.rs:47-64), and no lowered access carries a cache-policy attribute or !nontemporal (crates/rustinfer-kc/src/mlir/rocdl/helpers.rs:78, :154, :321-330), so the back end emits every global access at wavefront scope with no bit, the first column of both tables. Correct for the kernels on b057ef5, none of which needs a wider scope or a streaming hint; the cache-hints pass (RI-KC-016 (h)) and the hint field are planned in #64. The gfx950 ISA side is CDNA4-2, the gfx942 side FNUZ-3

Result

The kernel compiler on main writes code object V5 in the form the HIP loader requires, and its host tests now pin the header, the flags, the metadata note and the descriptor's segment sizes. The ROCm target reads every object before HIP sees it and refuses one that is not V5 ET_DYN for the device, or whose LDS or registers exceed it. On gfx950 the objects loaded and ran exactly (#45, #59). Two gaps remain: a few fields written by LLVM and lld still have no test (ABI-2), and no object has been loaded on gfx942 (ABI-3, #61); #61 also re-runs #45 on gfx950 at main, since PR #44 was rebased onto #58's target after the run. Gaps are on the tracker.
